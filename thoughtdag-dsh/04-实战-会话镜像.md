# 04 · 实战：把 DSH 会话变成可编辑的画布

这一篇是 **DSH 用户最值得看的部分**：插件不只是一个新画布，它能把你的现有会话读进来。

> **验证状态**：本篇操作路径与机制来自上游《Agent 对话地图》文档与插件手册 📄。本机已验证侧栏入口与画布启动 🧪；会话导入、增量追加等步骤**未在本文写作时逐步实测**，标注为 ⚠️ 的地方请以实机为准。

---

## 一、为什么值得做

Harness 的会话跑久了会被自动压缩（compact），最后只剩一段摘要，中间的推理和工具调用就看不到了。📄

镜像的做法是：**把每一轮、每次工具调用原样接进画布**，同时保证——

- 不改写原会话（原 Agent 想继续跑就跑，历史不动）📄
- 画布上的编辑只影响"这条镜像后续编译出的上下文"，不回写原会话 📄
- 原会话继续新增轮次时，画布**增量追加**在链尾，已有节点不移动 📄

一句话：**它是在 Agent 自带压缩之上的一层，而不是替代压缩。**

---

## 二、打开对话地图

两个入口：📄

1. 首次进入时，欢迎页选择 **Agent 对话**
2. 已在画布里，从**左上角画布菜单**打开 **Agent 对话地图**

界面分区：📄

| 区域 | 作用 |
|---|---|
| 最近工作 | 最近打开的 ThoughtDAG 画布，含已导入的会话镜像 |
| 项目文件夹 | 按会话记录里的工作目录分组，同项目的不同 runner 放一起 |
| 搜索与 runner 筛选 | 按标题过滤，或暂时隐藏某类 runner |
| 仅看变化 / 子线程 / 排序 | 聚焦新增内容、显示子线程、按时间/名称/大小排序 |
| 会话卡片 | 标题、runner、时间、大小；悬停出现导入/挂载/App/终端入口 |
| **接入** | 管理扫描来源和一键接入命令 |

---

## 三、哪些会话能被发现

支持四类来源：**Codex、Claude Code、DeepSeek Harness、Pi**。📄

- 只列**能明确识别格式**的文件，不按文件名猜
- Harness 插件内，DSH 会话由宿主直接从自己的会话目录提供，不依赖额外的桌面桥 📄
- 内置来源会自动探测各 runner 的标准目录；也能用「添加目录」授权其他目录 📄

**子线程**（Agent 自己派出的线程，如 Codex 子线程、Claude Code 子 agent）默认隐藏，打开开关后可见，且能独立成图。打开父会话时它们会一起进来：每次运行变成派出它的那一轮旁边的分支节点。📄

## 四、把一个会话导入成图

**做**：点会话卡片，或卡片上的**导入**图标。

**你会看到**：📄

- 每一轮「用户问题 + Agent 回答」变成一个**问答节点**
- tool call 与 tool result **配对成该节点的文本附件**，不会冒充成新的对话轮次
- 折叠状态下的节点面上会列出这一轮碰过的文件（✏️ 写/改，📖 读）
- 预览显示的是回答的结论段，而不是开头那句

保留三类来源信息用于追溯：runner 与 session id、每个节点对应的原始 turn 标识、tool call/result 与截断提示。📄

> **关键提醒**：导入可见 ≠ 已进入上下文。哪些内容真的进下一次请求，仍由连线、引用和附件开关决定。📄

## 五、增量追加：原会话继续跑，画布跟着长

手上有镜像后，回去让原 Agent 继续干活，画布会自己接上新轮次：

```
来源 session 新增 turn
      ↓
宿主发现会话文件变化（短暂去抖）
      ↓
对比 ledger（已导入到第几轮）
      ↓
只把新轮次接到该会话在画布上的尾部
```

遵守这几条规则：📄

- 不重复导入已记录的轮次
- **不移动现有节点**
- 用户改过的镜像内容不会被旧文本覆盖
- App 关闭期间的变化，启动或切回画布时补扫
- 一个会话登记在别的画布时，不会偷偷追加到当前画布
- **删掉某个 session 的全部镜像节点 = 解除订阅**，内容不会重新长回来

### 什么时候会停止监听

| 操作 | 是否解除监听 |
|---|---|
| 只删一条连线 | 否 |
| 修改节点文字 | 否 |
| 删除部分镜像节点 | 否 |
| **删除该 session 的全部镜像节点** | **是** |
| 撤销上面的删除 | 节点回来，但**订阅不会自动恢复**，需回地图重新打开该会话 |

📄 若新内容没出现：先在对话地图点**刷新**，再打开该会话卡片；仍不行就检查来源是否启用、会话是否还能被识别。

## 六、在镜像链尾追问：续接而不是另起

这是插件里最容易搞混的一点。同样是"在节点上提问"，结果完全不同：📄

| 你选的方式 | 发生了什么 | 会话日志 |
|---|---|---|
| 普通模型 | 只生成回答，不跑 Agent | 不新增 |
| **DeepSeek Harness · Agent** | Harness 执行真实 Agent 轮次（新会话），画布上下文通过 `inject` 先进去，然后才是你的问题 | 新增一条会话 |
| **在镜像链尾以 Agent 方式追问** | 续接对应的 Harness 会话（tail follow-up） | **原会话新增一轮**，画布同步 |

所以想"接着上次那条会话往下做"，记得在**镜像链尾**追问，并且选 Agent 方式。二者缺一，就变成另起炉灶。📄

## 七、把多个会话放进同一张画布

**做**：依次给两个以上卡片点**选入合并** → 底部出现多选栏 → 选择：📄

- **合并为新画布**：新建画布，各会话并排
- **合并入画布**：指定一张已有画布作为容器

**必须知道的规则**：各会话链之间**不会自动连线**。📄

原因就是核心法则——连线决定上下文。两个会话同时出现在一张画布上，并不代表它们之间建立了上下文关系；连不连、怎么连，由你决定。这既是安全边界，也是这套设计最有用的地方：**你可以在同一屏看到多个 Agent 的工作，却不让他们互相污染。**

---

## 八、从节点出发去别处干活，再把结果挂回来

节点右键菜单里有两个方向相反的入口（**以桌面版为准**，插件内的完整画布 UI 属上游 roadmap）：📄

| 入口 | 适合 | 挂回后的结构 |
|---|---|---|
| 带去 CLI 实验 | 验证假设、试替代方案，不想动主线 | 新 session 作为支线挂在出发节点 |
| 在 CLI 接续新章 | 上下文已整理好，继续主任务 | 新 session 接在主链尾部 |

机制：把所选节点的上游上下文编译成 Markdown 复制到剪贴板，里面带一个**回程锚点**；你在新 CLI 会话里粘贴继续干活，对话地图识别锚点后把新会话挂回原画布。📄

这不是自动调度：建会话、粘贴、后续操作都由你决定。📄

## 九、隐私与边界（别跳过这段）

| 事实 | 说明 |
|---|---|
| 镜像不改写原会话 | 原 runner 的历史不受影响 📄 |
| 导入不等于上传 | 扫描和深链只在宿主提供的受限桥接内运行 📄 |
| 但**调用远程模型时会发送内容** | 本地索引不代表检索结果永不离开设备：当 Agent 把结果用于远程模型请求时，命中的内容会随请求发出 📄 |
| 模型与凭证沿用 Harness | 插件不自带一套密钥体系 📄 |

想彻底不出本机：接本地 Ollama 或兼容 OpenAI 协议的本地端点。📄

## 十、本页可直接照做的三件事

- [ ] 打开 Agent 对话地图，确认能看到你的 DSH 会话卡片
- [ ] 挑一个**已经跑完**的中等长度会话，导入成图，双击某个节点看看 tool call 附件长什么样
- [ ] 回到 Harness 里对那条会话继续提一问，再回画布刷新，确认新轮次被追加到链尾而不是重建整张图
