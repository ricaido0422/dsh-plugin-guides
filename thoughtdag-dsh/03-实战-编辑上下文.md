# 03 · 实战：编辑上下文

> **本文的验证状态**：操作路径来自上游官方文档 📄；本机已确认"侧栏入口→画布启动"这一段 🧪，但**未在本文写作时实际跑过一次模型生成**，所以下面"你会看到"的部分标注的是文档描述的预期行为，不是本机截图证据。照做时如与描述不符，以你的实机为准，并欢迎提 Issue。

---

## 场景 0：先决定用哪种"运行方式"

画布右上角有模型选择器，里面区分两类东西，**别混用**：📄

| 选择 | 实际发生了什么 | 结果存在哪 |
|---|---|---|
| 某个普通模型（如 `deepseek-v4.1`） | 直接调该模型生成回答，**不跑完整 Agent 协议、不动工具** | 只存在 ThoughtDAG 画布 |
| **DeepSeek Harness · Agent** | 由 Harness 执行真实 Agent 轮次，可用工具，按你的 Harness 配置 | 画布 + Harness 会话日志 |
| 在已镜像的 Harness 会话链尾追问 | 续接那条会话，作为**新轮次**追加 | 原会话新增轮次，画布同步 |

一句话判断法：

- 只是想**琢磨思路、比几个说法** → 普通模型（快、便宜、不写日志）
- 想**真的动手干活**（改文件、跑命令、查代码） → DeepSeek Harness · Agent
- 想**接着上次那条会话往下走** → 在镜像链尾追问

⚠️ 常见误解：选普通模型 ≠ 在执行 Harness Agent。画布上出现节点，不代表 Harness 会话日志里多了一轮。

## 场景 1：提第一个问题，得到第一个节点

**做**：画布中间输入框输入问题 → 发送。

**你会看到**：一个问题节点 + 一个回答节点（或合成一个问答节点），卡片顶部是问题、中间是回答。回答流式生成，生成结束后卡片底部出现继续/重新生成/复制等按钮。📄

**如果没反应**：
- 模型选择器里没选模型 → 先去「连接模型」配置（见 [01](./01-安装与配置.md) 的配置之外，模型连接在 Harness 里配）
- 选了 Agent 方式但 Harness 侧没配凭证 → 换成普通模型试一发，先确认基础链路通

## 场景 2：沿路径追问，长出第二条节点

**做**：在第一个节点的底部输入框继续提问，或从节点连接点拖到空白处再输入。

**你会看到**：新节点出现在下方，节点之间有一条**紫色实线**。这条线意味着：第二问的请求里包含第一问的问答全文。📄

**为什么重要**：这就是"上下文"，它是可见的、可断的。等你想要第三问不带第二问时，直接删掉那条线即可。

---

## 场景 3：从一句话长出一条分支（探索）

这是 ThoughtDAG 最常用的动作，完整三步：📄

1. 在某个**回答里选中一句有价值的文字**
2. 点击浮动出现的 **探索**
3. 提交你的新问题

**你会看到**：一条**橙色实线**从原节点斜向长出，形成并行分支；**原路径不变**，原来那条链还在。

**什么时候用它**：要检验另一种解释、深挖某个细节、或者对比另一个模型的说法。主线继续往前走，探索留在旁边。

---

## 场景 4（核心实验）：断一条线，看回答怎么变

这是把这个工具从"好看"变成"有用"的那一步。设计成一个可复现的对照实验：

**准备**
1. 建一条三节点的链：Q1 → A1 → Q2 → A2（第二问依赖第一问）
2. 记下 A2 的回答要点，以及侧栏「将发送」显示的消息数/token

**干预**
3. 删掉 **A1 → Q2** 那条连线（只删线，不删节点）
4. 再点开 Q2 的「将发送」预览

**你会看到**
- 预览里的对话轮次明显减少，token 数下降 📄
- A1 节点**仍然在画布上**，只是不再进入 Q2 的请求 📄
- 用**同一个问题和同一个模型**重新生成 Q2，得到新版本 📄

**比较**
5. 在侧栏切换 Q2 的两个回答版本，对比差异

**为什么要这样设计**：删完线立刻用同问题同模型重跑，才把"上下文变化"和"换了提示词/换了模型"这两个变量分开。这是文档里明确推荐的做法。📄

**如果没看到预期**
- 删完线 token 没变 → 检查是不是还有别的入边（比如你之前拖过一条显式引用）
- 想恢复 → 连回去即可，节点从来没被删

## 场景 5：把实线换成虚线，省 token 不丢线索

**做**：选中那条紫色实线，在线的操作里把它从「完整结构上下文」转换成「摘要引用」。📄

**你会看到**：线变**紫色虚线**，token 估算立刻下降。区别在于：📄

| | 实线 | 虚线 |
|---|---|---|
| 上游每个回答 | 全文进入请求 | **不**进入 |
| 上游的问答与问题线索 | 进入 | 进入（摘要形式） |

**适合**：上游聊了很长但只想要"结论 + 推理脉络"的时候。整段贴进去往往只是噪音。

---

## 场景 6：用 `@` 和拖线做显式引用

两种方式把"另一条分支"的内容接进来，而不改变主线结构：📄

| 方式 | 操作 | 效果 |
|---|---|---|
| `@` 提及 | 输入框里打 `@`，选一个已命名节点 | 该节点作为显式引用加入请求 |
| 拖线引用 | 从节点连接点拖到**已有节点**上 | 建立显式引用连线 |

**和探索分支的区别**：探索是"从一句话出发新开方向"；引用是"把已有内容拉到当前请求里"。前者长出节点，后者只连边。

---

## 场景 7：上游改了，怎么知道哪些答案过期了

**做**：编辑某个上游节点的回答（点回答末尾的铅笔按钮），或改动上游的连线。

**你会看到**：依赖它的下游回答出现**琥珀色标记**，提示"该回答早于上游变化，需要检查或重新生成"。📄

三种处理：

| 操作 | 结果 |
|---|---|
| 原地重新生成 | 同节点新增一个回答版本，旧版本仍在 |
| 新建兄弟节点 | 两个答案在图上并排保留，方便横向比较 |
| 按依赖顺序重放 | 从某个点开始把下游重新跑一遍 |

📄 详见上游《版本、陈旧与重放》：`/zh/guides/versions-replay`

## 场景 8：整理一堆乱七八糟的探索

探索多了画布会乱，两个常用收敛动作：📄

| 动作 | 做什么 | 原路径 |
|---|---|---|
| **合并摘要** | 把一段连续、无分叉的内容压缩成一条摘要节点 | 保留 |
| **合并并删除** | 压缩的同时清掉中间节点 | 删除（谨慎） |
| **串联高光** | 把散落在各节点的重点句串成一条链 | 保留 |
| **凝练成副本** | 生成一份凝练副本，原路径和关键决策/转折节点受保护 | 保留 |

判断标准很简单：**这段过程以后还要不要回看**？要就"合并摘要/凝练"，不要才"合并并删除"。

## 一份可复制的练习清单

第一次用，建议按这个顺序做完，20 分钟能把核心机制吃透：

- [ ] 提 1 个问题，得到节点（场景 1）
- [ ] 追问 1 次，看见实线（场景 2）
- [ ] 选中一句话探索，看见橙色分支（场景 3）
- [ ] 打开「将发送」预览，记下 token
- [ ] 断一条线，再打开预览，看 token 变化（场景 4）
- [ ] 同问题同模型重新生成，切换版本对比
- [ ] 把一条实线转成虚线，再看 token
- [ ] 把断掉的线接回来，确认节点一直没丢

做完这 8 条，你就掌握了这个工具 80% 的日常用法。
