# 06 · 排错与常见问题

按"症状 → 先查什么 → 怎么办"排列。**先做诊断再做动作**，别一上来就重装。

---

## 侧栏没有 ThoughtDAG

按顺序查四件事：

| 查什么 | 怎么查 | 不符合怎么办 |
|---|---|---|
| 是否重启过 | 进程启动时间是否早于安装时间 | 重启，见 [01](./01-安装与配置.md) 第四节 |
| profile 对不对 | 安装命令写的是 `desktop` 还是 `web` | 装错就按 `--profile desktop` 重装 |
| 版本够不够 | 桌面端侧栏入口需要 **0.2.0-rc.2 起** 📄 | 升级 Harness |
| 装没装上 | `node_modules\dsh-thoughtdag` 是否真实目录 | 见 01 第五节三条验证 |

📄 官方 FAQ 对桌面版的答案就是这一组：装完重启、确认版本不低于 0.2.0-rc.2，侧栏入口依赖这个版本的面板槽。

---

## 插件列表显示新版本，装上去却是旧版本

**原因**：pnpm 默认压住发布不满 24 小时的版本。📄

**解决**：点名版本号安装。

```powershell
& $dsh plugin --profile desktop add dsh-thoughtdag@0.5.28
```

📄 官方原话："插件列表里看得到新版本号，不点名却会装到前一天的版本。"

## 画布一片空白

先分清是哪种情况：

| 场景 | 原因 | 处理 |
|---|---|---|
| 从源码自建后空白 | 构建时 base 路径被 Git Bash 的 MSYS 路径转换改写，导致资源请求全部回落到 HTML | 用 `npm run dsh:build` 构建，不要手工传 `--base=/thoughtdag/` 📄 |
| npm 装的插件空白 | 通常是宿主刚重启还没就绪，或会话未加载 | 重启后再点一次入口；仍空白则看宿主日志 |

📄 上游在开发说明里专门警告过这一点：手工传参会让 `dist-app` 烙进错误 base，"canvas mounts as a blank white page"。

---

## 画布能开，但模型列表是空的 / 生成失败

按这个顺序：

1. **Harness 里是否已配置模型与凭证** —— 插件不自带密钥，全部沿用 Harness 📄；缺失时画布自然拿不到可用模型
2. 模型选择器里选的是**普通模型**还是 **DeepSeek Harness · Agent** —— 后者要求 Harness Agent 链路可用
3. 换成本地端点试一发（Ollama 等），用来区分"网络/凭证问题"还是"插件问题"

---

## 节点有回答，但 Harness 会话日志里没有新轮次

**这是预期行为，不是 bug。** 📄

只有两种方式会写进 Harness 会话：

- 选 **DeepSeek Harness · Agent**
- 在镜像链尾以 Agent 方式追问

用普通模型生成的节点只属于画布。判断依据是"运行方式"，不是"节点有没有出现"。📄

---

## Agent 对话地图找不到我的会话

| 查什么 | 说明 |
|---|---|
| 会话是否在**这台机器**上 | 插件只能访问运行 Harness 的这台机器的受支持会话，不是任意浏览器的文件 📄 |
| 格式是否受支持 | 只列能明确识别格式的文件，不按文件名猜 📄 |
| 来源是否被停用 | 「接入」页里的复选框是否被取消 📄 |
| 是否已刷新 | 回地图点**刷新**再打开卡片 📄 |
| 如果是 Codex / Claude Code | 它们的目录（`~/.codex/sessions`、`~/.claude/projects`）要能被宿主读到 📄 |

## 装完没有 `/why`

先查版本。`0.5.3` 起才包含原生查询工具与 `/why`；`0.4.4` 没有。📄 再查配置里是否被设成 `whyTools: false`。

---

## 访问接口一直 401，是不是没装好

**不是。** Harness 宿主的鉴权在路由之前生效，不带 token 时 `/`、`/health`、`/plugins/...` 全部返回 401。🧪 本机逐条验证过。

所以**不要**用 HTTP 探测来判断插件装没装上，用 [01](./01-安装与配置.md) 第五节的方法。

---

## 装完别的插件好像少了东西

`dsh plugin add` 会顺带做依赖剪枝，日志出现 `+1 -4` 属正常。但值得跑一次完整性检查（[01](./01-安装与配置.md) 第七节）。🧪 本机 46 个依赖全部在位。

---

## 重启后插件全部消失 / 配置像被清零

这类"看起来回到全新状态"的问题通常不是插件坏了，而是**数据根目录或配置被改写**（例如异常关机导致的配置文件清零）。排查方向：

1. 先看 `~/.dsh/profiles/desktop/package.json` 是否还有你的依赖清单
2. 同目录下的 `.bak-*` 备份文件是否存在、时间是否对得上
3. 有备份就从备份恢复 `package.json` 与 `cordis.patch.yml`，再重启

⚠️ 这一条是通用经验，不是本插件的既有 bug；操作前务必备份现有文件。

---

## 一个总原则

排错时**优先怀疑版本与 profile**，其次怀疑配置，最后才怀疑插件本身。绝大多数"装了没用"是这两件事：装错了 profile，或者没重启。
