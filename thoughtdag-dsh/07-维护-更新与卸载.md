# 07 · 维护：更新、回滚、卸载

> 维护动作都会改 profile 配置，**做之前先备份**。下面每一步都给了备份命令。

---

## 一、备份（先做这个）

```powershell
$p = "$env:USERPROFILE\.dsh\profiles\desktop"
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
Copy-Item -LiteralPath "$p\package.json"        -Destination "$p\package.json.bak-$stamp"
Copy-Item -LiteralPath "$p\pnpm-lock.yaml"      -Destination "$p\pnpm-lock.yaml.bak-$stamp"
Copy-Item -LiteralPath "$p\cordis.patch.yml"    -Destination "$p\cordis.patch.yml.bak-$stamp"
```

🧪 这台机器的 profile 目录里本来就积累了几十个 `*.bak-*`，说明这是常规操作，不是多余动作。

---

## 二、更新

### 看有没有新版本

```powershell
npm view dsh-thoughtdag version
```

或直接看上游 Releases：<https://github.com/chenxiachan/thoughtdag/releases>

### 更新到指定版本

```powershell
$dsh = "D:\Program Files (x86)\DeepSeek\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop add dsh-thoughtdag@<新版本号>
```

**然后必须重启**（插件只在启动时挂载）。

📄 官方手册的更新办法就是这个：桌面版重新添加指定版本，再重启 Harness。

> 为什么不写 `@latest`？因为 pnpm 的 24 小时保护会让 `@latest` 落到旧版本，写精确版本号最可控。📄

### 更新后确认

```powershell
(Get-Content -LiteralPath "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-thoughtdag\package.json" -Raw -Encoding utf8 | ConvertFrom-Json).version
```

画布内出现新版本提示时，提示里写的操作就是这一步。📄

## 三、回滚

出问题时回上一个版本，命令与更新相同，只是版本号往回写：

```powershell
& $dsh plugin --profile desktop add dsh-thoughtdag@<上一个版本号>
```

如果 profile 已经乱了（比如依赖树被改坏），用备份恢复再重启：

```powershell
$p = "$env:USERPROFILE\.dsh\profiles\desktop"
Copy-Item -LiteralPath "$p\package.json.bak-<你选的时间戳>" -Destination "$p\package.json" -Force
& $dsh plugin --profile desktop install   # 按还原后的清单重装依赖
```

⚠️ 第二条命令会按 `package.json` 重装整套依赖，耗时较长，执行前确认备份时间点是对的。

## 四、卸载

```powershell
$dsh = "D:\Program Files (x86)\DeepSeek\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop remove dsh-thoughtdag
```

然后重启。检查三处都干净：

```powershell
$p = "$env:USERPROFILE\.dsh\profiles\desktop"
$j = Get-Content -LiteralPath "$p\package.json" -Raw -Encoding utf8 | ConvertFrom-Json
"依赖残留: " + [bool]$j.dependencies.'dsh-thoughtdag'
"清单残留: " + ($j.dsh.profile.bundles -contains 'dsh-thoughtdag')
"目录残留: " + (Test-Path -LiteralPath "$p\node_modules\dsh-thoughtdag")
```

三项都应为 `False`。

---

## 五、数据都在哪（卸载前想清楚）

| 内容 | 位置 | 卸载后 |
|---|---|---|
| 画布本体 | 浏览器 IndexedDB（Harness 桌面端的数据目录下）📄 | 默认保留，除非手动清 |
| 自动文件夹备份 / 导出 | 你自己设的备份目录、导出的 JSON 📄 | 保留 |
| why 层索引 | `~/.thoughtdag` 📄 | 保留 |
| 插件代码 | `profiles\desktop\node_modules\dsh-thoughtdag` | 随卸载删除 |
| 安装记录 | `profiles\desktop\package.json`、`pnpm-lock.yaml` | 随卸载改写 |

**结论：卸载插件不等于删掉你的画布。** 想彻底清理，需要另外处理 IndexedDB 与 `~/.thoughtdag`——那属于数据删除，卸载命令不会替你做。

## 六、版本对应关系

| dsh-thoughtdag | 说明 |
|---|---|
| `0.5.28` | 当前本机安装版本 🧪 |
| `0.5.3` 起 | 包含 why 四个原生工具与 `/why` 📄 |
| `0.4.19 – 0.5.18` | 用顶部浮动的「对话｜思维图」切换器，与宿主界面冲突较多 📄 |
| `0.4.4` | 没有 why 原生工具 📄 |

插件版本跟随主程序版本发布；每次 GitHub Release 也附带 `dsh-thoughtdag-<版本>.tgz`，`dsh plugin` 接受该文件的本地路径或链接。📄

## 七、日常维护节奏（建议）

| 频率 | 做什么 |
|---|---|
| 每次更新前 | 备份 `package.json`、`pnpm-lock.yaml`、`cordis.patch.yml` |
| 每次更新后 | 重启 → 看侧栏入口 → 跑一次完整性检查 |
| 每月一次 | 清理 `*.bak-*` 备份，保留最近 3 个即可 |
| 出问题时 | 先回滚版本，再排查配置，最后才重装 |
