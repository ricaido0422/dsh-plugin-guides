# 01 · 安装与配置

本篇只解决两件事：**怎么装进去**，以及**怎么确认它真的装进去了**。后者比前者更容易出错。

---

## 一、装之前先确认版本

### 1. 查 DSH 版本

插件要求 Harness **0.1.2-rc.1 或更新**；想看到侧栏入口，桌面版需要 **0.2.0-rc.2 起**。📄

Windows 桌面端可以直接查安装目录里的 `package.json`：

```powershell
$app = "D:\Program Files (x86)\DeepSeek\resources\app\package.json"
(Get-Content -LiteralPath $app -Raw -Encoding utf8 | ConvertFrom-Json).version
```

🧪 本机输出为 `0.2.1-rc.5`，满足要求。

> 安装路径不一定是这个。如果你的 Harness 装在别处，用任务管理器找到 `DeepSeek Harness.exe` 的实际路径，其上层 `resources\app\package.json` 就是同一处。

### 2. 查你实际在跑哪个 profile

这一步决定安装命令里的 profile 名，写错了会"装上了但界面里没有"。

```powershell
Get-CimInstance Win32_Process -Filter "Name='DeepSeek Harness.exe'" |
  Where-Object { $_.CommandLine -like '*dsh-desktop-host*' } |
  Select-Object -ExpandProperty CommandLine
```

命令行里形如 `C:\Users\<你>\.dsh\profiles\desktop` 的那一段就是答案。🧪 本机为 `profiles\desktop`。

`~/.dsh/profiles/` 下通常有 `desktop` 和 `web` 两套：

| profile | 归谁用 | 特征 |
|---|---|---|
| `desktop` | 桌面端 App 启动时加载的那套 | `package.json` 里依赖多，含你装过的各种插件 |
| `web` | 命令行 `dsh web` 起的网页版 | 依赖少，通常只有几个 |

两个 profile 的插件**互不相通**：装进 `web`，桌面端界面里不会有。

---

## 二、方式 A：插件页安装（官方推荐）

📄 官方手册对桌面版的描述：

1. 打开 Harness → 左侧「插件」页
2. 在列表里搜索 `dsh-thoughtdag`
3. 点安装
4. **重启一次 Harness**

想装当天刚发布的版本，在添加插件处直接输入 `dsh-thoughtdag@<版本号>`。

---

## 三、方式 B：命令行安装

`dsh plugin` 本质是把参数转给 profile 目录里的 pnpm，所以它支持 `add / remove / why` 等 pnpm 子命令。

```powershell
$dsh = "D:\Program Files (x86)\DeepSeek\resources\runtime\cli\bin\dsh.cmd"
& $dsh plugin --profile desktop add dsh-thoughtdag@0.5.28
```

🧪 本机实测输出（节选）：

```
dependencies:
+ dsh-thoughtdag 0.5.28
Done in 12.4s using pnpm v11.28.5
```

### 三个必须知道的坑

**① profile 名**

上游 README 首页写的是 `dsh plugin --profile web add dsh-thoughtdag`——那是**网页版**用法。桌面版要写 `desktop`。官方手册也明确："桌面版的配置名是 `desktop`，同一条命令换成 `--profile desktop` 也能从命令行给桌面版装"。📄

**② 版本点名**

pnpm 默认会压住发布不满 24 小时的版本。表现是：插件列表里明明显示新版本号，装上去却是前一天的版本。想装当天版本必须写死 `@0.5.28` 这种精确版本。📄

**③ 相对路径**

给本地目录（`file:...`）装插件时不要写相对路径，pnpm 会按当前工作目录解析并报 `ERR_PNPM_LINKED_PKG_DIR_NOT_FOUND`。一律写绝对路径。🧪（同类任务的既往经验）

---

## 四、装完必须重启

插件是**进程启动时挂载**的，不重启不会出现入口。📄

Windows 上有个坑：直接关窗口常常只是收进托盘，进程还在跑。

```powershell
# 1. 结束全部 DSH 进程（托盘会拦截正常关闭）
$ids = (Get-Process -Name "DeepSeek Harness" -ErrorAction SilentlyContinue).Id
if ($ids) { Stop-Process -Id $ids -Force }

# 2. 等 3 秒，确认真的没了
Start-Sleep -Seconds 3
Get-Process -Name "DeepSeek Harness" -ErrorAction SilentlyContinue

# 3. 重新启动（路径按你的实际安装位置）
Start-Process -FilePath "D:\Program Files (x86)\DeepSeek\Harness\DeepSeek Harness.exe"
```

> 重启不会丢会话：DSH 的历史写在磁盘上，重启后列表还在。🧪

## 五、怎么确认它真的装上了

按可靠性从高到低排列，**别只看第一条**：

### ① 看界面（最直接）

侧栏「插件」下方出现 **ThoughtDAG** 一行，点开是画布首页。🧪 本机以截图确认。

### ② 看物理目录

```powershell
$pkg = "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-thoughtdag"
$item = Get-Item -LiteralPath $pkg -Force
"存在: $([bool]$item)"
"属性: $($item.Attributes)"      # 出现 ReparsePoint 说明是软链，不是实体安装
(Get-Content -LiteralPath "$pkg\package.json" -Raw -Encoding utf8 | ConvertFrom-Json).version
```

期望：**真实目录**（`Attributes` 里没有 `ReparsePoint`）、版本号与你要装的一致。🧪 本机为 `0.5.28`。

### ③ 看启用清单

```powershell
$pj = "$env:USERPROFILE\.dsh\profiles\desktop\package.json"
$j = Get-Content -LiteralPath $pj -Raw -Encoding utf8 | ConvertFrom-Json
"依赖: " + $j.dependencies.'dsh-thoughtdag'
"已启用: " + ($j.dsh.profile.bundles -contains 'dsh-thoughtdag')
```

两个都要为真：写进了 `dependencies`，并且进了 `dsh.profile.bundles` 启用清单。

### ④ 别拿这些东西当判据

| 看起来能验证，其实不行 | 原因 |
|---|---|
| 访问 `http://127.0.0.1:<端口>/thoughtdag/` 看是否 200 | Harness 宿主的鉴权在路由之前生效，不带 token 时**任何路径都返回 401**，包括 `/`、`/health`。🧪 本机逐条验证过 |
| `~/.thoughtdag` 目录是否存在 | 这是 why 层的索引目录，按需生成；刚装完不存在是正常的 |
| `dsh --profile desktop --dump-config` | desktop profile 由 Electron 独占管理，会被拒绝 |
| 宿主 `/plugins/...` 状态接口 | 同样 401 |

## 六、配置项

插件自带的 patch 层已经写好默认值，挂在 `insert` 下、id 为 `thoughtdag`。📄（包内 `cordis.patch.yml`）

| 配置项 | 默认 | 作用 |
|---|---|---|
| `mountPrefix` | `/thoughtdag` | 画布 SPA 挂载的路径前缀 |
| `trustedHosts` | `[]` | 除 localhost / 127.0.0.1 外，额外允许的 Host 头 |
| `whyTools` | `true` | 是否注册 `why_check / why_file / why_find / why_recall` 四个原生工具 |
| `whyPrompt` | `true` | 是否往系统提示里加一段"改文件前先查历史"的规则 |

### 关掉 why 层

如果你不想让 Agent 多出这四个工具，在 profile 的用户层 `cordis.patch.yml` 里覆盖同名 id 的配置：

```yaml
- id: thoughtdag
  config:
    whyTools: false
    whyPrompt: false
```

> ⚠️ **不要**在用户层 `cordis.patch.yml` 里新增一个 id 也叫 `thoughtdag` 的条目——插件包已经自带该条目，重复会报 `duplicate loader entry id`。要改就改已有条目的 config，或直接改包的默认值。🧪（同类任务的既往经验）

## 七、装完的完整性检查

`dsh plugin add` 会顺带做依赖剪枝，日志里出现 `+1 -4` 这类数字属正常，但值得花一分钟确认没剪坏别的插件：

```powershell
$pj = "$env:USERPROFILE\.dsh\profiles\desktop\package.json"
$nm = "$env:USERPROFILE\.dsh\profiles\desktop\node_modules"
$j  = Get-Content -LiteralPath $pj -Raw -Encoding utf8 | ConvertFrom-Json
$missing = @()
foreach ($k in $j.dependencies.PSObject.Properties.Name) {
  if (-not (Test-Path -LiteralPath (Join-Path $nm $k))) { $missing += $k }
}
if ($missing) { "缺失: " + ($missing -join ', ') } else { "全部依赖在位" }
```

🧪 本机 46 个依赖全部在位，所有非内置 bundle 都能解析。
