# 05 · 按需：历史查询（why 层）

> 如果你只想要画布，这一篇可以先跳过。它讲的是插件附带的另一块能力：**让 Agent 在动文件之前，先查这块代码的历史**。

> **验证状态**：工具名、参数、默认开关均来自插件包自述 📄（`dsh-thoughtdag` README 与包内 patch 配置）。本机只确认了配置项存在 🧪，四个工具的实际调用**未实测**。

---

## 一、它解决什么

Agent 改代码最常见的失败不是"改错了"，而是"不知道这里为什么是这样"。

`git log` 能看到提交，但看不到"当时为什么这么定"。why 层查的是**对话历史**：这个问题以前问过没有、这块文件在哪些轮次被讨论和改动过、原话是怎么说的。

它和 DSH 自带的检索区别在于：**有出处、可回溯到具体轮次**，而不是给你一段语义相近的文字。

---

## 二、四个工具

插件把 CLI 的库直接打包进来了（`lib/why.mjs`），**不需要另装 CLI 或 MCP**。📄

| 工具 | 参数 | 作用 |
|---|---|---|
| `why_check` | `path` | 先检查这个对象**有没有历史**，避免后续白查 |
| `why_file` | `path`，可选 `include_read`、`limit` | 返回相关轮次与观察到的改动 |
| `why_find` | `phrase`，可选 `in`、`limit` | 精确查找问题/回答/材料中的词句 |
| `why_recall` | `session`、`turn` | 读取一个完整轮次 |

配套还有一个聊天命令：

```
/why <文件路径 | 网址 | arxiv:id>
```

它直接把 CLI 的 `why` 输出贴回来，**不额外发消息给模型**，也就几乎不花 token。📄

---

## 三、推荐的调用顺序

给 Agent 用，也给自己用，顺序是有讲究的：

```
why_check(path)          ← 先问"有没有"
   ↓ 有
why_file(path)           ← 再看"哪些轮次碰过、改了什么"
   ↓ 需要原话
why_recall(session, turn) ← 最后读完整的一轮
```

直接上 `why_file` 的问题在于：对象可能根本没有历史，白花一次调用。📄（`why_check` 的存在意义即此）

---

## 四、两个必须知道的限制

**① `why_find` 不是语义搜索**

它是**精确词句**查找。想找"当初为什么把超时改成 30 秒"，得用它真实出现过的字眼。📄

**② 候选解释 ≠ 已核验的原因**

工具返回的是"相关轮次和观察到的改动"，不是"这件事的原因"。把相关性当因果，是这个工具最容易被误用的地方。📄 上游原文就写明："候选解释也不等于已核验的原因。"

---

## 五、路径怎么解析

- 相对路径按**当前 Harness 会话的工作目录**解析 📄
- 索引与 CLI 共享同一个 `~/.thoughtdag` 目录 📄
- 这个目录是**按需生成**的：刚装完没有、还没积累过对话时没有，都正常 🧪

---

## 六、默认是开的，怎么关

`cordis.patch.yml` 里两项默认 `true`：📄

| 项 | 关掉后 |
|---|---|
| `whyTools: false` | 不注册四个工具与 `/why` 命令 |
| `whyPrompt: false` | 不往系统提示里加"改文件前先查历史"那段规则 |

只关提示、留工具，是很常见的折中：模型不会被强制去查，但你（或它自己判断时）仍可调用。

改法见 [01-安装与配置](./01-安装与配置.md) 第六节（注意不要新增重复 id）。

---

## 七、隐私

本地索引 ≠ 永不外发。当 Agent 把 why 的结果用于一次**远程模型请求**时，命中的历史内容会随请求一起发出去。📄 在意这一点的话，把模型换成本地端点。

---

## 八、为什么装的是 0.5.28 而不是更早

上游文档写明：`0.5.3` 起才包含这四个原生工具与 `/why`；`0.4.4` 没有。📄

所以如果你在别处看到"装完没有 `/why`"，先查版本，别怀疑安装方式。
